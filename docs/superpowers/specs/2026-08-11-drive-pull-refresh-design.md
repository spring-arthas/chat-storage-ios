# 网盘下拉刷新设计

## 目标

修复网盘列表下拉后弹出“网盘操作失败”的问题，并把刷新动画从搜索框区域移动到当前目录名称右侧。搜索、当前目录和传输中心固定，只滚动目录与文件列表。

## 根因

`DrivePlaceholderView` 把 `.refreshable` 挂在包含目录栏、传输中心和内容列表的整体 `ScrollView` 上，因此系统刷新动画只能出现在搜索框下方。刷新动作调用 `DriveViewModel.load()`，会重新请求根目录树、恢复旧路径、加载当前目录子目录和文件第一页；普通下拉刷新被扩大成整棵目录树重建，任一额外请求失败都会弹错。

## 方案比较

1. 保留 `.refreshable`：实现最少，但系统动画位置不能移动，不满足需求。
2. 自定义 SwiftUI 下拉检测：用滚动几何记录下拉距离、松手后刷新当前目录，动画可放在目录名旁。采用该方案。
3. 用 `UIScrollViewRepresentable` 包装 `UIRefreshControl`：能自定义更多交互，但会引入 UIKit 状态同步和列表手势冲突，本次没有必要。

## 状态与数据流

- 首次进入仍调用 `load()`，负责加载根目录树和文件第一页。
- 下拉只调用 `refreshCurrentDirectory()`。
- 当前刷新并行请求当前目录的直接子目录和文件第一页，两个请求都成功后一次性替换列表。
- 刷新不调用 `roots()`，不改变 `path` 和当前目录 ID。
- 刷新失败保留旧目录、旧文件和分页状态，只设置可见错误信息。
- 独立使用 `isRefreshing`，不复用首次加载的 `isLoading`。
- 切目录、搜索或其他内容加载发生后，旧刷新响应通过内容版本和目录、搜索条件校验丢弃。

## 页面结构

- 外层固定区域：搜索栏、目录栏、传输中心。
- 内层 `ScrollView`：只包含目录和文件列表。
- 下拉距离达到 72pt 后进入待刷新状态，用户松手时触发一次刷新。
- `isRefreshing == true` 时在当前目录名称右侧显示小型 `ProgressView`，标识为 `drive.refresh-indicator`。
- 内容不足一屏时仍允许垂直回弹，以便触发下拉刷新。

## 验证

- 单测证明下拉刷新不再调用 `roots()`。
- 单测证明刷新后仍在原目录。
- 单测证明刷新失败保留旧内容。
- 单测证明 `isRefreshing` 在请求期间为 `true`，完成后恢复为 `false`。
- 编译 iOS 工程，并在模拟器确认搜索栏、目录栏和传输中心固定，动画位于目录名右侧。
