# 对话、网盘与动态增强设计

## 目标

在保留现有消息、网盘和“我的”布局语言的基础上，新增一个 Twitter 风格的“动态”主 Tab，并让聊天消息、聊天附件和网盘文件都能自然进入动态发布链路。

## 产品范围

### 动态

- 主 Tab 位于“消息”和“网盘”之间，顶部提供“关注”和“我的”两条时间线。
- 卡片结构采用头像、昵称、账号、相对时间、正文、媒体网格和互动栏。
- 发布器支持 500 字、最多 4 个照片或 1 个视频；媒体沿用现有上传链路，每个资源显示准备、上传、成功和失败状态。
- 支持下拉刷新、游标分页、点赞/取消点赞、回复、转发、分享和删除自己的动态。
- 点赞、转发采用即时本地反馈；服务端拒绝时恢复原状态并展示真实错误。
- 从聊天或网盘发起时，发布器自动带入引用卡片，用户仍可补充文字。

### 对话

- 聊天设置增加“查找聊天内容”，按全部、照片与视频、文件三个类型筛选。
- 消息长按增加“分享到动态”；文字作为引用摘要，附件保留真实 `fileId`，不重复上传。
- 收藏消息入口升级为“稍后处理”，保留现有账号隔离缓存语义。

### 网盘

- 固定顶部增加智能集合：全部、最近、图片、视频、大文件。
- 智能集合只筛选当前已加载目录数据，不改变服务端目录结构，也不影响选择、下载和删除。
- 文件菜单增加“发布到动态”；媒体文件生成可预览引用，普通文件显示文件名、类型和大小。

## 架构

- iOS 新增 `Features/Dynamics`，分为模型、仓库、视图模型和 SwiftUI 页面。
- `DynamicComposerRouteStore` 是主界面共享的轻量路由，只保存一次性发布草稿，不持有页面或网络对象。
- 动态媒体复用 `ChatAttachment`、`ChatAttachmentUploading` 和现有媒体预览服务。
- net-server 延续已存在的 `0x60/0x61` 动态雏形，在 `0x60-0x6F` 内补充时间线、详情、互动和删除，不改聊天、好友、文件帧。
- `user_dynamic.image_paths` 兼容旧逗号路径和新的附件 JSON；新互动数据使用独立表，避免把点赞和回复塞入动态主表。

## 协议

| 帧 | 方向 | 用途 |
| --- | --- | --- |
| `0x60` | 客户端→服务端 | 发布动态 |
| `0x61` | 服务端→客户端 | 发布回执 |
| `0x62/0x63` | 请求/响应 | 时间线分页 |
| `0x64/0x65` | 请求/响应 | 点赞、取消点赞、回复、转发 |
| `0x66/0x67` | 请求/响应 | 动态详情及回复分页 |
| `0x68/0x69` | 请求/响应 | 删除自己的动态 |

所有新字段均为 JSON 可选字段，旧客户端不会发送这些帧，现有 Android 和 macOS 的登录、聊天与网盘链路不受影响。

## 数据与安全

- 时间线只包含自己和有效好友的未删除动态。
- 删除必须校验 `dynamic.user_id == loggedInUserId`，采用逻辑删除。
- 点赞使用唯一键 `(dynamic_id, user_id)` 保证幂等；取消点赞只逻辑删除自己的记录。
- 回复限制 280 字；动态正文限制 500 字；附件必须是当前用户可访问的文件 ID。
- 服务端日志只记录动态 ID、用户 ID、数量和长度，不打印正文、附件地址或令牌。

## UI

- 颜色继续使用 `AppTheme.primaryGreen`，但时间线保持 Twitter 式高信息密度白底卡片和细分隔线。
- 发布按钮使用右下角悬浮圆形按钮；发布页为全屏 Sheet，左侧取消、右侧发布。
- 动态正文支持展开；媒体网格根据 1、2、3、4 项自适应；视频叠加播放标识。
- 空态、加载态、分页态、上传态和失败重试都在当前区域呈现，不用阻塞式全屏等待。

## 验证边界

- iOS：模型解码、请求编码、分页合并、乐观点赞回滚、发布校验、智能集合、聊天引用草稿均有单测。
- net-server：帧编号、鉴权、可见性、幂等点赞、回复、删除权限和分页均有测试。
- 不启动模拟器；先跑通用 iPhone 架构构建和可运行的单元测试。真机离线时明确记录未执行的安装和人工 UI 验收。
