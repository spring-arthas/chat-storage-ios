# iOS 网盘媒体全屏预览设计

## 目标

只修改 iOS 网盘文件列表的打开体验：点击图片后直接进入全屏预览，按图片原始宽高比完整居中显示；点击视频后直接进入全屏播放器并自动播放，不再先弹出底部 Sheet，也不再要求用户二次点击“全屏”。普通 PDF、Office、文本等文件继续沿用现有下载后 Quick Look 流程。

## 当前问题与根因

1. `DrivePlaceholderView` 把图片和视频统一写入同一个 `preview` 状态，再通过 `.sheet(item:)` 展示 `DrivePreviewView`，所以视频必然先出现底部弹框。
2. 视频 Sheet 内部又维护 `showsFullscreenVideo` 并使用第二层 `.fullScreenCover`，导致“点文件 -> 弹框 -> 点全屏”多一步操作。
3. 图片虽然使用了 `.scaledToFit()`，但外层是横向和纵向同时开启的 `ScrollView`。双向滚动容器会给内容无界尺寸，图片按自身尺寸展开后只显示局部，`.scaledToFit()` 没有以设备可见区域作为明确约束。

## 方案比较

### 方案 A：所有文件统一改成 `.fullScreenCover`

改动最少，但 PDF 等普通文件也会改变现有呈现方式，扩大了本次需求范围，不采用。

### 方案 B：媒体与普通文件分开路由（采用）

图片和视频进入独立的全屏媒体状态，普通文件继续使用 Sheet + Quick Look。图片以设备可见区域为边界做 `.fit` 布局，视频直接渲染当前播放器的全屏形态。该方案改动集中，不影响下载、分享、视频续签和普通文件预览。

### 方案 C：改成 UIKit 自定义预览控制器

可以提供更复杂的转场和手势，但需要重写当前 SwiftUI 播放控制，风险和维护成本高，本次不采用。

## 组件设计

### 预览路由

- `DrivePlaceholderView` 分开保存媒体预览和普通文件预览状态。
- `showPreview(for:)` 只创建图片或视频的媒体预览，并触发 `.fullScreenCover`。
- `downloadAndOpen(_:)` 继续创建普通文件预览，并触发现有 `.sheet`。
- 图片和视频复用现有 `DrivePreview` 数据，包括远程播放地址、续签闭包、本地分享闭包和安全作用域。

### 图片全屏预览

- 使用黑色全屏背景。
- 图片布局以全屏可见区域为明确约束，使用 aspect-fit 完整显示，不裁剪、不拉伸。
- 图片尺寸小于屏幕时允许自然居中；尺寸大于屏幕时缩小到完整可见。
- 顶部提供关闭和分享入口；本次不增加编辑、旋转或强制缩放手势，避免超出需求。

### 视频全屏播放

- 点击文件后直接进入 `.fullScreenCover`，播放器自动开始加载和播放。
- 复用现有 `DriveVideoPlaybackController`、`SecureVideoSurface`、URL 续签、失败重试、暂停、停止、进度拖动和分享下载逻辑。
- 播放画面继续使用 `AVLayerVideoGravity.resizeAspect`，保证视频完整显示。
- 全屏状态直接开放横屏；关闭预览后恢复应用竖屏策略并释放播放器。
- 删除网盘视频预览中的二次全屏状态和“进入全屏”按钮，只保留明确的关闭按钮。

## 数据流

1. 用户点击文件列表条目。
2. `DriveFileOpenRules` 判断图片、视频或普通文件。
3. 图片：下载到临时预览缓存后写入媒体预览状态，直接全屏展示。
4. 视频：优先获取签名播放地址和续签闭包，写入媒体预览状态，直接全屏播放；取地址失败时保留现有本地预览降级路径。
5. 普通文件：下载到目标目录后写入普通文件预览状态，继续用 Quick Look Sheet。
6. 关闭媒体预览时清空状态；视频同时恢复方向策略并使播放器失效。

## 错误处理

- 图片文件解码失败时，在全屏页面显示“无法预览图片”，仍提供关闭入口。
- 视频加载、续签或播放失败时沿用现有错误覆盖层和“重新加载”。
- 图片或视频预览地址获取失败时沿用 `DriveViewModel` 当前错误提示。
- 不修改服务端接口、视频播放端口、下载协议或传输任务逻辑。

## 测试与验收

1. 更新 UI 测试：点击视频后应直接出现全屏容器、播放、停止和进度控件；不再存在“进入全屏”按钮。
2. 增加图片全屏 UI 测试入口和布局标识，证明点击图片后直接进入全屏、使用完整显示容器并可关闭。
3. 保留并运行现有播放器状态机、URL 续签、失败重试、横竖屏策略和分享安全测试。
4. 运行 Drive 专项测试、全部单元测试、iPhoneOS Debug 编译和 `git diff --check`。
5. 自动化测试只能证明路由和布局约束；最终图片视觉比例和真机视频全屏由用户在 iPhone 上验收。

## 不在本次范围

- 不修改聊天图片或聊天视频预览。
- 不修改普通文件 Quick Look。
- 不增加图片编辑、删除、轮播或复杂手势。
- 不修改 `net-server`。
